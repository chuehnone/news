# 校準驗算程序（calibrate / drift）

**這是評分校準的唯一出處。** `/news-importance-score` 與 `/update-news` 兩個 skill
都指向這裡，不要在任何 SKILL.md 內另抄一份——2026-08-20 抽出前，兩份手抄版本
已經各自漂移（一份引用 `CALIBRATE_SA_MULTIPLE` 等常數、另一份沒有；處理順序
第 3 步一份寫「回頭讀 `anchors`」、另一份寫「回頭讀『固定錨點』表」）。
這正是 CLAUDE.md「schema 常數只能有一份」要防的同一種病。

## 評完必跑

```bash
python3 /Users/chinsheng/Documents/Projects/news/news.py calibrate
```

拿這批與**固定錨點**（`ANCHOR_START`~`ANCHOR_END`）比 S/A 佔比。
`add` 只在超過 `CALIBRATE_SA_MULTIPLE`（2.5 倍）時印一行紅線提醒，
**完整診斷要自己跑，不論 `add` 有沒有印紅線**。

⚠️ **不要用「跟昨天比」代替這一步**——那是循環論證（兩天都落在已經墊高的
區間裡），實測已經漏掉整整四天的漂移（2026-07-25~28，每天都回報「與前期一致」）。

## 紅線亮了不等於漂移

它是「停下來查一眼」的訊號（2026-08-17 實測）：那天當日累計 14 則、
S/A 佔比 20%、達錨點 3.5 倍，但 `drift` 顯示未漂移，決策相關性反而收緊 -4.5%、
後期整體 A 級佔 4% 低於錨點的 5.7%。批次補滿後比例自然降到 13%。

**批次量小時，兩則實質 A 級就能把百分比推高**（`CALIBRATE_MIN_BATCH` 設 10
就是這個道理，但當日累計會跨過那條線）。

## 亮紅線時的處理順序

1. 跑 `python3 news.py drift` — 它有主題控制，是區分「標準鬆了」與「當期新聞
   真的更重要」的**唯一**依據。`calibrate` 分不出這兩者，它的報表也明說了。
2. `drift` 說沒漂 → 小樣本雜訊，**維持原標準繼續評**。
   不要為了讓數字好看而壓低後續分數——那本身就是另一種漂移。
3. `drift` 說有漂 → 回頭讀 `news.py anchors` 的前期範例（即
   `/news-importance-score` 的「固定錨點」表）重新對照，
   **不是調門檻遷就現況**（門檻一改，前後資料就永久不可比）。

## 回報時怎麼寫

**calibrate 那欄不能省，亮紅線時要加註 `drift` 的結論**，例：

```
calibrate S/A 20%（3.5 倍）→ drift 未漂移，小樣本
```

只報則數不報佔比的話，評鬆了的批次與正常批次在報表上長得一模一樣——
而漂移的全部危險就在於它每天看起來都正常。
